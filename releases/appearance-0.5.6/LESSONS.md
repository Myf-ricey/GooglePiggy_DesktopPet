# 本线程经验与成果

最终交互契约与移植步骤见 [WINDOWS-HANDOFF.md](WINDOWS-HANDOFF.md)，本文件记录为什么这样做。

1. **从原代码取默认值。** 原对话框由奶油到浅粉渐变、玫瑰边框组成。一个接近白色的 RGB 不能代替整套默认外观；“未自定义”应保留为单独状态，恢复默认删除自定义值，重走原渲染路径。
2. **透明度分层。** 不透明度施加在窗口/最终画布会连字和猪一起变淡。先分开背景、按钮底色、文字；框背景在合成后统一 alpha，避免多个半透明形状叠加后失真。像素测试验证 25% 背景与近 100% 字形。
3. **预览必须落在真实位置。** 窗口旁的孤立样张不能判断与猪的关系。预览共享正式渲染器和定位规则，以原生屏幕坐标跟随猪；用样例任务，不触发真实已读/权限逻辑。
4. **reset 和 UI 会话是两套状态。** 关闭重建设置窗口会清掉勾选、跳动窗口。恢复默认原地更新 slider/color well，只重置持久外观值。
5. **图层归属决定变换。** 灯泡虽然在更新类中绘制，视觉上属于猪。已拆出 drawPetDecoration，在 dialogTransform 之外绘制；尾巴独立窗口也必须显式乘 petScale。仅缩放主图不等于整体缩放。
6. **绘制、命中、边界一起变。** 字号和按钮应随框缩放；鼠标点用逆变换；可见边界用正变换。调整间距时更新 canvas 范围并固定脚部屏幕锚点，避免放大剪裁或点击错位。
7. **跳转与未读逻辑解耦。** 是否打开会话不能取决于任务完成与否；清蓝点必须继续遵守既有成功/已读确认规则。
8. **不要把旧 Mac 工作目录当最新跨平台基线。** 本地旧 main 缺少 Windows 0.5.4/0.5.5；本次实际 fetch 后从远端建立独立分支，移入本线程改动，未将无关旧 Python/PowerShell 文件上传。完整 Mac 回归也因此使用了远端已有的正确庆祝断言。
9. **证据分级。** 单元/像素测试验证变换与 alpha；录屏验证原生播放组合效果；Windows 性能、点击与更新回滚仍要实机验证。三者不能互相冒充。

# Suggested skills

- `gitnexus-debugging`：已有 Windows 索引可用时追踪渲染与输入调用链；无索引时直接读当前源码，不拿其他仓库结果代替。
- `diagnose`：若出现帧率或输入回退，固定场景、复现、记录样本时间与 pending/acknowledge 顺序。
- `handoff`：把 Windows 最终实现提交、版本、验证证据和剩余风险追加为下一份交接。
