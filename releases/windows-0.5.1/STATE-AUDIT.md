# 桌宠状态遗漏复查 · 2026-10-17

结论：上次是兼容场景与验收覆盖遗漏，不能归为随机意外。本轮又补齐了相邻缺口；修复后，在本报告覆盖的状态场景中未发现可复现的剩余异常。

当前构建标识：`20261017.3-state-audit`，产品版本仍为未发布的 `0.5.1-windows`。正式运行目录是 `dist/GifPigDesktopPet`，最新交付是本目录的 ZIP；`dist-candidate`、`dist-hotfix` 为此前测试构建。

## 发现与处理

| 项目 | 证据与处理 |
| --- | --- |
| 压缩日志解码上限偏低 | 旧值仅 64 KiB；真实本机 236 个候选压缩日志的解码窗口大于该值。改为受限的 64 MiB，并以 17 MiB 合法日志验证；这不表示 236 条任务都曾显示错误。 |
| 压缩日志尾部截取漏事件 | 改为流式逐行读取生命周期，跳过超大工具输出行，保留时间最新的有效状态；不将聊天全文展开到磁盘。 |
| 空明文遮蔽压缩副本 | 空 `.jsonl` 会回退 `.zst`；非空的新明文仍优先，避免旧压缩副本结束新任务。 |
| 最近 256 条元数据遗漏旧任务 | 本机数据库已有 401 条记录。保留近期扫描上限，同时对实际发出 Hook 的 actor 与活跃节点定向查询，防止漏结束记录或误当未登记内部会话。 |
| 时间与缓存边界 | 生命周期按有效时间选择；非法时间不伪造结束状态。活跃或读取失败的日志每 15 秒复查，覆盖保持文件大小／mtime 的替换情况。 |
| 压缩上下文后继续同一回合 | 新的 `PreToolUse` 可以恢复；单独迟到的 `PostToolUse` 不恢复，真正 Stop 后也不能复活。此项是定向场景补强，本机旧记录未出现该连续序列。 |
| 多个本地候选构建易混淆 | 心跳及交付来源记录增加构建标识，并逐一比对运行 EXE、最终 ZIP 与源码 overlay 哈希。 |

## 验证

先运行新增测试，8 个场景均在旧实现中失败；随后修复并通过。

- 50 项回归：原 Windows 20、更新 16、内部记忆会话 2、压缩日志 4、本轮状态审查 8。
- Windows PowerShell Hook 自测通过。
- 新构建 EXE：12 项原生动画／并发／权限／隐藏／休息回放通过。
- 新构建 EXE：6 项隔离观察器验收通过，包括旧 actor 超过 256、空明文旁的较大压缩日志、真实新回合、压缩后继续执行、重启不复活旧小猪、结束后清空活跃家庭。子进程 PATH 排除 Python 与 WindowsApps。
- 实机只读核对：当时只有当前检查任务活跃，没有活跃子任务，也没有“日志已完成但状态仍运行”的矛盾。
- 三份独立审查覆盖观察器、状态／Hook、UI／更新／构建；修复后再由独立审查核验，修改范围内未发现可复现剩余缺陷。

## 已核实的保护机制

1. 重复 token 和旧回合事件不能复活已结束任务。
2. 中断／压缩期间迟到工具结果不能冲掉状态屏障。
3. 父任务结束而真实子任务仍运行时，家庭仍保留工作状态。
4. 权限气泡优先于更新气泡，更新等待权限和拖动完成。
5. 更新校验完整文件清单与哈希；helper 只等待指定路径的原进程。
6. 原安装路径、自启动及 Hook 配置保留，旧版备份可用于恢复。
7. zstandard 原生依赖随 EXE 打包，最终包与运行 EXE 内容一致。

## 覆盖范围

本机 Windows 11、150% 单屏。其他物理多屏／缩放、真实断电恢复和正式线上发布仍属于此前已列明的未实测项。异常或超限日志保留最后可信状态，不用通用超时伪造任务完成：压缩输入上限 64 MiB、解压总量 128 MiB、单条待解析行 1 MiB，明文尾部扫描上限 16 MiB。损坏或不支持的未来 Codex 格式不在“全部正常”的承诺范围内。

以上测试使用合成数据或对现有日志的只读核对；未开启 memories，未修改 Codex 数据库或聊天日志，未上传 GitHub。
